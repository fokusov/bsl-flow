**Приостановлено по просьбе пользователя. Точная точка продолжения: [BENCHMARK_CHECKPOINT_2026-09-10.md](BENCHMARK_CHECKPOINT_2026-09-10.md).**

Состояние на 2026-09-10: managed OpenCode adapter реализован и включён в маршрутизацию контроллера. Реальные проверки транспорта, локального изменения и одного source-only MCP инструмента прошли. Codex с отдельным набором скиллов и полный CLI lifecycle четырёх профилей ещё проверяются. Это не результат бенчмарка и не готовый релиз.

## Реализованные компоненты

- `New-BSLFlowToolsetSnapshot.ps1` создаёт отдельный полный снимок скиллов и скриптов, фиксирует SHA-256 и проверяет точный состав. Защищает от перезаписи, обхода пути, reparse points и очевидных файлов авторизации. Снимок проверяется перед запуском и после него.
- `Task.Execution.ps1` проверяет явный профиль: provider, native executable и sandbox с хешами, выбранный toolset и его хеш, приватные запрещённые roots; для Unica — bootstrap, manifest, каждый из 66 файлов runtime и точные имена source tools.
- `OpenCode.ps1` запускает весь host и его дочерние инструменты через Windows sandbox, готовит отдельные config/data/cache/state/tmp каталоги, передаёт prompt через stdin, сохраняет процесс и результат. Профиль, модель, этап, prompt и source path входят в binding. Неполная попытка не запускается повторно автоматически.
- `OpenCode.Events.ps1` проверяет полный многопроходный JSONL: session/message/part/call identities, последовательность шагов, явный allowlist инструментов, terminal stop и структурированный результат. Неизвестные/ошибочные/оборванные события блокируют приёмку.
- Контроллер связывает профиль с intent и dependency hashes, маршрутизирует worker/reconcile/verification через выбранный host. Старые запросы без профиля сохраняют прежний маршрут.
- Профильный spec critic использует отдельную сессию выбранной reviewer-модели, вложенные исходные требования/спеку, существующий rubric, общую валидацию и прежние пороги. Глобальная модель packaged reviewer не подставляется молча. Способ строгого ограничения инструментов Codex critic ещё проверяется.

OpenCode разрешён только для измеренной пары `1.18.30` / `deepseek/deepseek-v4-flash`, без неподтверждённого effort override (`null`). Sandbox — native Codex `0.154.0`, elevated. Обновление executable или скиллов требует обновления явно зафиксированной идентичности.

## Измеренные особенности Windows и host

Штатный `windowsSandbox/setupStart` завершился успешно после временного managed-профиля app-server. Глобальный `danger-full-access` не переписывался; штатная настройка переключила Windows backend на elevated, резервная копия config.toml сохранена вне репозитория.

`unelevated` не поддерживает нужный запрет чтения. На проверенном elevated backend одного `:root=none` недостаточно, чтобы утверждать запрет чтения. Явный запрет отдельного приватного каталога подтвердился и для основного, и для дочернего PowerShell. Запрет родительского каталога с попыткой открыть вложенный worker не сработал: CreateProcessWithLogonW 267. Поэтому исходники, controller state и host scratch разделены на соседние деревья.

Перед dispatch проверяются чтение/запись controller, чтение/запрет записи config, запись scratch и доступ source согласно этапу. Каждый `denied_read_roots` задан явно и связан с хешем профиля. Синтетическая проверка не является попыткой чтения каждого реального приватного root, в частности базы. Доступ к остальному диску не заявляется как deny-by-default.

OpenCode требует заранее создать `config/opencode/.gitignore`; конфиг остаётся read-only. Помимо XDG config/data/cache нужен XDG state, иначе lock-файлы пытаются создаваться в глобальном профиле. Чистое окружение сохраняет необходимые системные Windows-переменные, но не произвольные секреты родителя.

Unica bootstrap требует запись в `runtime_cache/.locks` даже при уже готовом runtime. Разрешена только эта служебная запись; executable tree остаётся read-only. Не разрешены установка runtime, его замена и durable jobs. В OpenCode профиле Unica отключён bash, MCP вызывается по точным нормализованным именам.

## Реальные результаты и стоимость

Успешный source smoke создал `edited.txt` с точными ожидаемыми байтами. Повторный разбор сохранил ту же session и не сделал нового запроса. Найден и исправлен сбой сравнения сохранённого receipt из-за decimal → JSON → double.

Для Unica использован **созданный с нуля заведомо неполный XML**, без исходников проекта, метаданных или данных базы. Модель прочитала выбранный SKILL.md и вызвала `unica_unica_cfe_validate`; валидатор вернул ожидаемые две ошибки и одно предупреждение. Это доказательство маршрута инструмента, а не корректности расширения.

По 19 сохранённым сессиям OpenCode сообщил суммарно **0.0493475808 USD**, включая неуспешные smoke и CLI-прогоны. Учёт делает `Get-BSLFlowOpenCodeCost.ps1` по всем `step_finish.part.cost`, без повторного подсчёта cached replay. Это сообщённая стоимость, не сверка с биллингом. `observed_model` и `observed_effort` остаются `null`: запрос модели не является независимым подтверждением backend identity.

Локальные raw evidence находятся в ignored `work/benchmark-integration`. Ключ DeepSeek передаётся через environment дочернего host; он доступен самому процессу и потенциально его инструментам. Этот маршрут не заявляет изоляцию секрета от модели или запрет сетевой эксфильтрации. Автоматически публиковать raw каталоги нельзя: публикация требует отдельного очищенного набора результатов, без ключей, prompt/private данных, cache и содержимого базы.

## Критерий завершения интеграций

1. Реальные source-only вызовы выбранных наборов в обеих host/model связках.
2. Одинаковый публичный CLI lifecycle для четырёх профилей: успешный путь, failure/repair/recovery, неизменность обязательных этапов и отсутствие смешивания скиллов.
3. Проверка профиля reviewer, полного учёта затрат всех стадий и лимита сравнительного запуска.
4. Независимое ревью и обязательные регрессии зафиксированной сборки.
5. После этого — backup bp1 и сравнительные задания; результаты среды отделяются от ошибок модели и framework.

Пока все пункты не подтверждены, матрица четырёх связок не объявляется готовой.

## Дополнительные наблюдения 2026-09-10

cc-1c-skills требует готового Python с lxml. Первый прогон нашёл другой интерпретатор через поиск по сторонним каталогам и не принят как соблюдающий сценарий. Второй был заблокирован после обращения glob выше worker. После явного OpenCode --dir, точного пути source в prompt и проверенного Python 3.12.14 / lxml 6.1.1 третий прогон выполнил только выбранный скилл и синтетический XML в нужных каталогах. Получены ожидаемые 2 ошибки / 1 предупреждение. Зависимость Python ещё нужно включить в воспроизводимый профиль среды бенчмарка.

Пустая таблица mcp_servers={} в Codex app-server не отключает глобальные серверы. Адаптер сначала читает только конфигурацию, сохраняет только имена и отключает каждый глобальный сервер перед inventory. Это проверяемый снимок настроек, не блокировка файла от конкурентного изменения. Штатный exec отдельно использует --ignore-user-config. Живое подтверждение исправления ещё требуется.
