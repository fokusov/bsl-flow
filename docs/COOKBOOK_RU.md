# Рецептник BSL Flow

Рецепты задают границы задачи и наблюдаемую проверку. Названия метаданных всегда сверяй с выгрузкой: пример не заменяет grounding и не разрешает работу с базой.

## 1. Печатная форма

**Класс и риск:** S, low; M, если меняются несколько форм, права или внешняя печать.

**Требуемое поведение:** GIVEN документ и существующий макет WHEN пользователь вызывает команду печати THEN формируется табличный документ с согласованными параметрами; при отсутствии макета выводится диагностика и данные не записываются.

**Проверки:** static для имён объекта/макета и BSL; build внешнего артефакта, если он поставляется; Vanessa для команды, параметров и ошибки. **Ошибки агентов:** придумывают имя макета, вызывают `Записать()` при печати, смешивают форматирование и выборку данных. **Grounding:** неизвестный объект/макет, неэкспортный общий модуль, отсутствующий реквизит параметра.

## 2. Реквизит и управляемая форма

**Класс и риск:** M, medium; L при миграции заполненных данных, правах или нескольких формах.

**Требуемое поведение:** GIVEN новый и существующий объект WHEN форма открывается и пользователь меняет реквизит THEN значение сохраняется по правилам объекта, а обязательные связанные поля валидируются перед записью.

**Проверки:** metadata grounding, static, integration на запись, Vanessa для начального значения, ошибки и прав. **Ошибки агентов:** задают дефолт только в форме, пишут объект в обработчике изменения, обходят штатную проверку перед записью. **Grounding:** точное имя реквизита, форма-владелец, клиент/серверный контекст и экспортность вызовов.

## 3. Движения по регистру

**Класс и риск:** M, high; L при пересчёте истории или денежных остатках.

**Требуемое поведение:** GIVEN документ с известными данными WHEN он проводится THEN создаются только ожидаемые движения с измерениями, ресурсами и периодом; отмена проведения снимает именно эти движения.

**Проверки:** static, unit для преобразования строк, integration в копии базы с проверкой записей регистра, Vanessa для сценария пользователя. **Ошибки агентов:** путают измерение и ресурс, не учитывают отмену проведения, пишут движения вне транзакции. **Grounding:** регистр, набор записей, типы измерений и существующая точка проведения.

## 4. Изменение проведения

**Класс и риск:** M/L, high.

**Требуемое поведение:** GIVEN документ в каждом допустимом состоянии WHEN выполняется проведение или отмена THEN меняются только оговорённые записи и статусы, а ошибка не оставляет частичного результата.

**Проверки:** integration на повторное проведение, отмену и отказ; Vanessa на пользовательский маршрут; при необходимости нагрузочный smoke. **Ошибки агентов:** смешивают проверку формы с проведением, повторно пишут наборы без очистки, меняют прошлые периоды без правила. **Grounding:** обработчик проведения, регистры, блокировки, права и транзакционные границы.

## 5. HTTP-сервис

**Класс и риск:** M, high; L для публичного контракта, авторизации или денежных операций.

**Требуемое поведение:** GIVEN валидный запрос с разрешённой аутентификацией WHEN endpoint вызывается THEN возвращается документированный статус и JSON; невалидный запрос не меняет данные и не раскрывает секреты.

**Проверки:** static, unit сериализации, integration с локальным mock-клиентом, контрактные негативные случаи; runtime только на разрешённом контуре. **Ошибки агентов:** доверяют входным полям, логируют токены, делают неидемпотентную повторную запись. **Grounding:** HTTP-сервис, шаблон URL, роли, экспортные методы и схема XDTO/JSON.

## 6. Регламентное задание

**Класс и риск:** M/L, high.

**Требуемое поведение:** GIVEN расписание и допустимый запуск WHEN задание срабатывает THEN обрабатывается ограниченный набор данных, результат идемпотентен и ошибка записана без бесконечного повтора.

**Проверки:** static, unit фильтра, integration с контролируемым запуском в тестовой базе, проверка журнала и повторного запуска. **Ошибки агентов:** запускают задание при разработке, не ограничивают выборку, скрывают исключения. **Grounding:** метаданные задания, серверный общий модуль, права, блокировки и журнал регистрации.

## 7. EPF-отчёт

**Класс и риск:** M, medium; L при записи в базу или внешней интеграции.

**Требуемое поведение:** GIVEN параметры отчёта WHEN пользователь формирует отчёт THEN вывод отражает согласованную выборку и пустой результат объясним; отчёт не меняет данные без отдельной команды.

**Проверки:** static, native build, round-trip, native load/open exact SHA-256, сценарий формирования в разрешённой базе. **Ошибки агентов:** считают build доказательством поведения, меняют данные в форме отчёта, теряют параметры при round-trip. **Grounding:** внешняя обработка/отчёт, форма, СКД, макеты и права.

## 8. Обмен данными

**Класс и риск:** L, high.

**Требуемое поведение:** GIVEN пакет известной версии WHEN он импортируется THEN валидные объекты обрабатываются идемпотентно, ошибки локализованы и повтор не создаёт дубликаты; формат и направление обмена сохранены.

**Проверки:** static, unit маппинга, integration на fixture-пакет и повтор, Vanessa для наблюдаемого статуса, контракт с внешней стороной. **Ошибки агентов:** меняют ключ идентификации, отправляют живой пакет при отладке, превращают частичную ошибку в «успех». **Grounding:** планы обмена, конвертации, регистры сведений, идентификаторы и границы транзакции.

Для каждого рецепта фиксируй `original-task.md`, spec, выбранные проверки и реальный статус доказательств. Локальный lint или build не заменяет runtime-приёмку.
