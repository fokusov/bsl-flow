# Pre-registered decision rules (Ф6.5)

These rules are fixed **before** any benchmark run they will be used to judge, per
`docs/plans/2026-09-26-remediation-plan.md` section Ф6.5. Do not edit this file to fit a
result after the fact; if a rule needs to change, that change is its own dated entry below
with the reason, made before the next run it applies to.

## Rule 1 — keep a component

A Core component (a skill, a hook, a piece of bootstrap) stays enabled by default only if,
compared to the mode without it (typically `bare` vs `core`):

- it cuts the **false-PASS rate** OR the **mean scope drift** by at least 20% (relative,
  not absolute), AND
- wall-clock time increases by at most 50%.

If neither the false-PASS nor the drift improvement reaches 20%, or the time cost exceeds
50%, the component is a kill-list candidate (moved to `managed/experimental/` per Ф0.2,
unless an ADR records an explicit exception).

## Rule 2 — council for M-sized tasks

The review council is enabled by default for `M`-sized tasks only once it is shown, across
the M tasks in the benchmark set, to find defects that a single reviewer misses in at least
15% of M tasks (i.e. `council_only_defect_rate >= 0.15`, computed from the
`council_only_defects` / `m_task_count` metric in `bench/Measure-BenchResults.ps1`'s output).
Until that threshold is met, council for M stays off by default.

## Rule 3 — kill-list closure

Every entry opened in Ф0.2's kill-list is closed (kept, removed, or moved to
`managed/experimental/`) using Rule 1 against the aggregated results in
`bench/results/<date>.json`. A component with no benchmark coverage cannot be kept by
default — it either gets a task added to the starter set or is treated as removed pending
coverage.

## How the runner's metrics map to these rules

- **False-PASS rate** = `false_pass_count / total_task_attempts`, where a false PASS is the
  agent's final message claiming success/PASS while hidden acceptance is FAIL (see the
  heuristic in `bench/Invoke-BSLFlowBench.ps1`'s `Get-BenchClaimedOutcome`).
- **Scope drift** = mean of `drift_line_count` (changed lines outside `expected_scope`) plus
  `drift_new_metadata_count` (new metadata objects outside the task's spec) across task
  attempts in a mode.
- **Time increase** = `(mean_wall_seconds[mode] - mean_wall_seconds[bare]) / mean_wall_seconds[bare]`.
- **Council-only defects** = defects present in the council's report but absent from the
  single-reviewer report for the same M task, as already tracked by the existing council
  test suites (`Test-CouncilValidation`, etc.); the benchmark only aggregates the count, it
  does not re-implement council scoring.
