# Оригинальный запрос

## Запрос пользователя (2026-09-27, планирование будущей версии)

> еще я бы хотел чтобы в bsl-flow спека и ревью после исполнения проверялись агентами под разными углами. Например, с точки зрения безопасности, с точки зрения оверинжиниринга, нет ли "велосипедов" и можно было упростить архитектуру. И так далее. Пока давай это обдумаем, как добавить в bsl-flow чтобы оно органично вписалось туда. При этом имеем в виду что можем работать как в Codex, Claude, Opencode

## Решения пользователя в ходе обсуждения

- Сейчас это только план на будущую версию; реализация в текущем релизе не выполняется.
- Один общий механизм «линз» для spec review и code review; первым выпускается code review после исполнения, потому что в Core у него нет контракта.
- Исполнение гибридное по риску: M — один изолированный reviewer проходит все выбранные линзы за один проход; L/high — каждая линза в отдельном изолированном агенте; хост без параллелизма выполняет линзы последовательно в свежих контекстах; недоступный изолированный запуск даёт `BLOCKED` без тихого downgrade.
- Каталог линз в первом релизе фиксирован и поставляется с BSL Flow; формат линзы сразу пригоден для расширения, проектные линзы открываются позже.
- Пользователь может настроить провайдера, модель и effort отдельно для каждого критика (линзы).
- Дизайн по секциям (архитектура, схема и вердикт, адаптеры хостов, конфигурация моделей, маршрутизация/managed/тестирование/этапы) подтверждён пользователем.

## Контекст планирования

На момент планирования: spec review для M — один reviewer по рубрике с метриками оверинжиниринга, для L/high — Council с критиками `intent_critic`, `architecture_critic`, `executability_critic` и chair. В Core code review формального контракта не имеет: есть только шаг 5 `1c-verify` для L/high и агент `bsl-flow-code-reviewer` для Claude Code. Managed-поверхность заморожена ADR-11.
