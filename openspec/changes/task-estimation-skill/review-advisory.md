# Advisory post-publication notes

> Независимая сверка inline-реконсилиации council (schema v2) подтвердила все 19 находок и 16 protected-пунктов (см. `review-reconciliation.json`). Этот файл — фактические поправки для реализатора: chair в четырёх резолюциях использовал имена/маркеры, которых нет в проекте. Финальный опубликованный текст `spec.md` не меняется (хеш забинден в `review.json` / финальной валидации); поправки применяются на этапе реализации и фиксируются в references скилла.

## Поправки имён артефактов и маркеров

| В финальном тексте spec.md | Фактически в проекте | Где в спеке |
|---|---|---|
| `lint-results.json` с `passed: true` | `spec-lint.json` (артефакт `Test-1CSpec.ps1`, поле `passed`) | п.2; Критерии приёмки №1; Требуемые проверки / Integration |
| BLOCK-находки из `review-findings.json` | `review.json` (schema v1/v2, findings с `severity=blocker`, сверяется с `review-reconciliation.json`) | п.2 |
| маркер `task_type=spike` в change-метаданных | такого поля в OpenSpec schema `bsl-flow` нет; маркер — явная пометка в `original-task.md`/`spec.md` либо явный запрос пользователя | п.9 |
| модель по умолчанию `bsl-flow-worker-default` | плейсхолдер; конкретные значения модели/effort по умолчанию задаются константами в references скилла (в `bsl-flow.yaml` единого ключа worker-модели нет) | п.6 |

## Уточнение формулировки (п.10)

«Пометка об устаревании» в `estimate.md` не может быть статичной: файл фиксирует хеши и дату генерации, а предупреждение об устаревании показывает скилл при последующем чтении после сверки хешей с текущими файлами.

## Вывод

Вторая итерация модельного ревью не выполнялась: поправки не меняют объём, границы или архитектуру, уточняют только имена реальных артефактов. Managed-stage интеграция и конфигурируемость якорей остаются за пределами v1 согласно принятым находкам R-002/R-003/R-015.
