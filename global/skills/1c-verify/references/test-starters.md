# Стартовые заготовки YAxUnit и Vanessa

Генератор `scripts/New-1CTestStarter.ps1` создаёт в проекте `tests/bsl-flow-starter` только
отслеживаемые заготовки: исходный модуль YAxUnit, рецепт интеграционного отката, feature пилота Vanessa
и рецепт readonly-проверки UI. Машинно-зависимые `VAParams.json` и `va-run.json` сохраняются только
в игнорируемом `.bsl-flow/local/test-starter`. Генератор не запускает 1С, не устанавливает
расширения и возвращает статус `runtime_unverified`.

Для Vanessa обязательно передай абсолютные пути FILE-базы, EPF Vanessa и каталога отчётов, имя
пользователя и свободный порт. Имя TestClient по умолчанию выводится из project path; workstation setup
передаёт project-derived имя и проверенный на момент генерации порт из диапазона 48000–48999. Генератор создаёт новый профиль TestClient и передаёт его явно:
`DisableLoadTestClientsTable` предотвращает загрузку сохранённой пользовательской таблицы, а
`ДанныеКлиентовТестирования` содержит именно созданный профиль. Это следует из локальной
документации Vanessa `docs/CommandSetting/CommandSetting.md`; символ `;` внутри JSON для `/C`
экранируется как `\;`. Учетные данные не записываются: пароль параметром не принимается.

Сначала выполни только `pilot-engine.feature`. Его успех доказывает лишь выполнение assertion
движком Vanessa, но не подключение TestClient, выбранный порт или профиль, а также не UI и не
метаданные базы. Профиль остаётся `runtime_unverified`, пока отдельный поддерживаемый сценарий
явно не подключит TestClient и не зафиксирует его имя/идентичность и фактический порт. Готовая
feature для этого не поставляется: шаг подключения нужно сверить с версией Vanessa и проектной
базой. Затем привяжи рецепт fixture к подтверждённому SafeMode:
данные держи в локальном игнорируемом файле либо передавай через разрешённый проектный адаптер;
не ослабляй SafeMode и не добавляй инфраструктуру метаданных только ради заготовки.

Для интеграции выбери реальные операцию и read-only запрос состояния. Проверь изменение внутри
транзакции, всегда вызови `ОтменитьТранзакцию()` и отдельно прочитай состояние после отката.
Внешние эффекты транзакцией не откатываются. Для UI сохраняй уникальный marker в run-manifest;
проверяющий тест только читает созданный ранее объект и не повторяет создание после сбоя.
